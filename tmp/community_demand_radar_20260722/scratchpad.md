# 社区真实需求扫描 Scratchpad

日期：2026-07-22

## 目标

从 Reddit、Hacker News、Indie Hackers、GitHub 等社区的一手讨论和行为记录中，寻找可以迁移 Traffic.cv 产品结构、但更加实际的需求。

## 需求判定标准

只有同时满足多数条件才进入候选：

1. 至少两个独立用户/帖子出现同类问题。
2. 用户已经采用 spreadsheet、email、复制粘贴、自建脚本或昂贵软件绕行。
3. 问题具有持续频率，而非一次性咨询。
4. 漏掉或处理慢会造成收入、时间、罚款或客户流失。
5. 能明确指出付费主体和购买预算来自哪里。
6. 数据获取、合规和单人维护边界可接受。

## 待验证假设

| 假设 | 需要的社区证据 | 状态 |
|---|---|---|
| 小商家需要竞争对手价格/库存变化提醒 | 手工检查、现有工具太贵或误报、明确用于定价 | 需求已验证，但通用市场拥挤；仅保留垂直切口 |
| 服务商需要更窄的招标/许可/商机筛选 | 邮件噪音、错过截止日、已有付费 | 需求存在，但行业销售成本高，暂不优先 |
| 本地商家需要跨平台评论/问答/线索收件箱 | 多平台手工切换、响应慢损失客户 | App 评论工作流已验证；通用本地商家收件箱未验证 |
| 房东/物业经理需要证照、保险、租约到期管理 | 表格、漏期罚款、现有软件过重 | 强需求，但低价竞争多；需渠道或派工门禁差异化 |
| 独立站卖家需要退款/拒付证据与异常监控 | 手工拼证据、直接金钱损失 | 强需求，但 Chargeflow 等已高度产品化，不优先 |
| 自由职业者/小代理商需要应收账款跟进 | 手工催款、现金流损失、现有会计软件不足 | 强需求，但基础提醒已商品化；仅剩催收执行层 |
