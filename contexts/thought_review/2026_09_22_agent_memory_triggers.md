# Agent 与记忆的调度和触发

日期：2026-09-22。问题：已理解记忆类的存储与检索实现，如何把它接入 Agent 的运行流程？

## 控制权

记忆模块提供操作能力。调用时机由应用流程、Agent 工具循环或后台任务决定。模型只能使用当前请求中可见的消息；数据库中的记忆需要被读取并加入消息，才会影响本轮推理。

- 应用触发：请求进入后检索，拼接上下文后调用模型；结束后按策略提取和写入记忆。
- 模型选择工具：工具描述随请求提供给模型；模型输出调用请求，运行时执行记忆工具，把结果放回消息，继续调用模型。
- 后台触发：会话结束、条数或 token 阈值、定时任务触发整合和清理；需要显式编排。

注册工具只让能力可用，不保证每轮调用。Prompt 可以指导选择，但强制执行要求由程序保证。MemoryManager 管理类型分发和检索合并，与决定什么时候调用模型属于不同职责。

## 教学例子

用户第一次说“我是前端工程师，请用 TypeScript 举例”。应用或模型工具调用提取偏好并写入。下次用户问“解释一下闭包”时，可以在回答前由应用查询偏好并加入上下文；也可以让模型按工具描述自主检索。前者确保流程执行，后者保留按需选择，但可能漏查。

同会话历史消息与跨会话持久化记忆是两条路径。当前消息已包含偏好时，模型可以直接使用；换会话后需要重新加载或检索。一次请求可包含多次模型调用，每次工具返回后继续推理都需要把结果加入消息。

## 最小设计判断

学习阶段先写显式流程：检索 → 构造消息 → 模型生成 → 按策略提取并保存。需要复杂按需回忆时再加入工具调用；需要异步整理时再加后台任务。教学中的 extract_memory、build_messages 等名称是自定义伪代码，不代表 HelloAgents 的现有 API。
