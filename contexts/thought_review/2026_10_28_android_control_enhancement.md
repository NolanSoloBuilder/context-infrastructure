# 安卓手机操作增强建议｜2026-10-28

用户场景：Mac 连接安卓手机，需在雪球等 App 中批量管理自选、分组，并可由用户随时观察和接管。本文最初为方案建议。

实施进度：同日用户授权先接入 scrcpy，已安装5.0.1并通过 `~/Applications/Android投屏.app` 完成实机投屏、鼠标点击/右键返回和中文粘贴验证。记录见 `contexts/survey_sessions/2026_10_28_scrcpy_setup/report.md`。uiautomator2 尚未部署，批量流程升级仍为后续建议。

结论：建议使用 scrcpy 提供可见投屏与鼠标键盘操作，配合基于控件的 UI 自动化处理批量任务。单独增加 scrcpy 不能自动解决控件定位、等待条件和结果核对问题。

## 刚才任务的实际瓶颈

- 原有脚本通过 ADB 反复调用 `uiautomator dump`、读取 XML、解析坐标。每次界面读取都有进程与导出开销。
- 快速 `adb input text` 在当前输入法和手机组合上出现字符遗漏；通过逐字输入和读取输入框校验完成任务，但中文通过拼音候选输入，步骤较多。
- 部分文字标签本身不响应点击，需要定位对应可点击父容器或复选框。
- 添加自选后的推荐关注弹窗，以及页面切换后的异步更新，需要额外识别。
- 从每只股票详情反复打开新搜索页，累积了较深的返回栈，最后回到主页的步骤偏多。
- 已完成的有效措施应保留：代码和市场匹配、只补缺失自选、保留既有分组、保存后重新打开核对、最终在各组主页读回名单。

## 建议组合

| 组件 | 用途 | 局限 |
| --- | --- | --- |
| scrcpy | 本地实时投屏，键鼠操作，观察弹窗，方便人工接管；一般粘贴路径可用于中文字段验证 | 不提供适合直接按控件语义操作的完整自动化接口；默认 SDK 键盘注入对非 ASCII 有限制；中文粘贴仍需实机验收 |
| openatx/uiautomator2 | 通过设备端 UiAutomator 服务和 Python 客户端，按文字、resource ID、状态定位，等待控件与核对勾选状态 | 需部署和管理设备端组件；部分自绘界面仍可能缺少节点；不能在这台手机尚未实测时承诺性能提升倍数 |
| 现有 ADB | 设备连接、诊断、必要回退与环境检查 | 不继续把逐字符注入、每一步单独导出 XML 当成批量任务的默认主路径 |

scrcpy 官方说明支持 USB/TCP 投屏、键鼠控制、macOS，不要求 root 或长期安装一个手机端 App。其控制文档区分正常剪贴板粘贴与按键事件注入：后者可能破坏非 ASCII 内容，因此不能笼统声称默认键盘模式即可完美输入中文。

## 最小实施顺序

1. 先接入 scrcpy，并实测当前手机的画面、点击、返回、中文普通粘贴；不先改动已有自选数据。
2. 按当前工具和权限条件评估控件自动化接入；通过控件 ID/文字和实际勾选状态操作，画面用于核对与缺失节点时的回退。
3. 把雪球流程改成可重复执行的同步：输入目标清单、先检查现状、只补差异、按条件等待、最后统一读回。重新运行不得重复添加，也不撤销用户后来手工加入的内容。
4. 同一手机同一时间只保留一个写入控制者；用户手动接管后暂停自动点击并重新读取界面。
5. 以少量股票完成新增、已存在、归组、重跑四种情形的实机验证后，再用于批量任务。

不把此方案扩展为证券自动交易。价格预警、持仓或交易账户操作需按用户后续的具体任务范围另行处理。
