# 浏览器视频下载 Skill 设计

## 目标

用户提供一个视频页面链接后，Codex 自动复用本地 Chrome 会话，发现页面实际加载的媒体资源，将视频保存到本机，并返回文件路径与校验结果。

首期只支持小红书普通视频笔记。后续按站点适配器扩展，不承诺处理 DRM、付费墙或需要绕过访问控制的媒体。

## 推荐形态

采用“薄 Skill + 浏览器资源发现 + 确定性下载脚本”，不单独开发浏览器扩展：

1. Skill 接收页面 URL 和可选输出目录。
2. Codex Chrome 插件复用用户当前登录态，打开页面并等待播放器加载。
3. 通过 `pageAssets` 获取浏览器已经观察到的 `video` 资源；必要时用 CDP 读取已发生的媒体请求。
4. 下载脚本接收媒体 URL、页面 Referer 和目标路径，使用本机 HTTP 客户端保存文件。
5. 下载后检查文件大小、容器、时长、音视频编码和可播放性，再返回绝对路径。

浏览器只负责访问和资源发现。下载、断点续传、文件命名、重试和校验放入脚本，避免把可重复逻辑交给页面交互。

## 网页产品形态

纯前端网页不适合作为可靠实现。目标站点的 CORS、登录态、临时媒体签名、反自动化策略和浏览器下载限制，会让“粘贴链接后由网页直接抓取”频繁失败；把用户 Cookie 提交到远端服务也会引入明显的账号安全风险。

长期合理的网页形态是“Web 控制台 + 本地浏览器助手”：

1. 用户在网页粘贴链接并创建下载任务。
2. 本地 Chrome 扩展或 Codex 本地代理接收任务，在用户浏览器中打开目标页面。
3. 本地助手从已加载页面中发现媒体请求，只把任务状态和必要元数据回传给网页。
4. 视频默认由本机直接下载到用户选择的目录，媒体内容和登录凭据不经过业务服务器。
5. 网页展示进度、历史记录、文件信息，并可追加提取音频或本地转写任务。

如果只做个人本机工具，可以进一步简化为 localhost Web App：网页 UI、任务服务和下载器都运行在本机，Chrome 扩展只负责页面媒体发现。若要做成多人 SaaS，再增加账号、设备配对、任务通道和权限审计。

## 输入输出合同

输入：

- 必填：视频页面 URL
- 可选：输出目录、文件名、是否提取音频、是否生成逐字稿

输出：

- 下载文件的绝对路径
- 来源页面 URL
- 文件大小、时长、分辨率和编码信息
- 明确的完成、需要登录、需要 CAPTCHA、未发现媒体、签名失效或不支持状态

默认输出目录可设为 `~/Downloads/Codex Video Downloads/`。临时媒体签名 URL 不写入长期日志。

## 安全与边界

- 不读取 Chrome Cookie 文件、Local Storage、密码或浏览器 Profile。
- 只使用页面正常加载时浏览器已经观察到的媒体 URL。
- 登录或 CAPTCHA 阻塞时交给用户完成，不绕过访问控制。
- 只处理用户明确提供的页面，不做批量抓取。
- 带签名 CDN URL 通常会过期，发现后立即下载；失败时重新加载页面获取新签名。
- DRM、付费内容和受访问控制保护的媒体直接返回不支持。

## 实施顺序

1. 创建 `download-page-video` Skill。
2. 实现小红书适配器和通用 HTTP 下载脚本。
3. 用一条公开笔记、一条需要登录的笔记和一条失效链接做验收。
4. 验证下载文件可播放、文件元数据完整，并确认无浏览器敏感数据读取。
5. 运行 Skill 校验工具，再决定是否扩展到其他站点和 HLS。
