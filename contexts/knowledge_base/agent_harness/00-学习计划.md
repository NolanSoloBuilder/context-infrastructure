## 六周路线

| 2 · Managed Runtime | 跑一个 Temporal TypeScript 样例，把 I/O 移到 Activity，观察重试和 Event History。对照 LangGraph 的 thread 与 checkpoint，说明各自恢复什么。DDIA 选读事务、分布式系统的故障和流处理。 [Temporal 样例](https://github.com/temporalio/samples-typescript) · [Workflow Execution](https://docs.temporal.io/workflow-execution) · [Activity Definition](https://docs.temporal.io/activity-definition) · [LangGraph Persistence](https://docs.langchain.com/oss/python/langgraph/persistence) · [DDIA](https://dataintensive.net/) | 用本地数据库持久化 run、已完成步骤和工具回执。另起 worker 验证两处故障：审批等待时退出、提交已落库但 worker 尚未记录步骤完成时退出。恢复后只产生一次领域提交，仍能查到回执。用事件序号做 SSE 重连练习，服务端重发时客户端按序号去重。 |
| 3 · Context / Memory / Knowledge | 结合 Mindspace 手册读 Anthropic 的 compaction、按需检索、结构化笔记。Chip Huyen 的《AI Engineering》先读 Dataset Engineering、Evaluation Methodology 和 RAG，跟着本周实验读对应段落。 [Context Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) · [AI Engineering](https://www.oreilly.com/library/view/ai-engineering/9781098166298/) | 把当前设计修订和已确认硬约束作为权威输入，把长历史压缩成可追溯摘要。比较全量历史与按需检索两版，记录输入 token、关键约束保留率和旧版本误用率。加一条跨 workspace 检索拒绝用例。 |
| 4 · Tool / MCP / Sandbox | 用 BeamJoin 本地工具作为例子，读 MCP 的 confused deputy、token passthrough 和 scope minimization。画出用户、Agent、工具执行器与目标服务之间的授权链。 [MCP 安全规范](https://modelcontextprotocol.io/specification/latest/basic/security_best_practices) | 将审批绑定到用户、项目、基准修订、提案内容哈希和有效期，执行前重新校验。验证跨项目、已过期、提案被替换、工具结果诱导执行越权命令这四类情况。若练代码执行，用隔离进程限制文件、网络和时间，并验证限制实际生效。 |
| 5 · Evaluation & Evolution | 用 Promptfoo 跑一组 A/B，读 Anthropic 对 task、trial、grader、transcript、outcome 的划分。 [Promptfoo](https://github.com/promptfoo/promptfoo) · [Demystifying evals for AI agents](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) | 建议从 20 个 case 开始：8 个正常任务、6 个冲突或恢复、6 个权限或注入。用领域回读核对结果，用 trace 排查路径。对比两版 Prompt 或工具描述，记录任务成功率、工具调用次数、成本、耗时、越权次数和重复提交次数。安全与幂等用确定性断言做硬门禁，真实模型结果汇报样本数及重复运行波动。 |

## 主练项目

做一个本地的「可恢复设计修改」实验。优先用独立目录、脱敏设计输入和假的领域服务。主链路是发起设计修改→预览→用户确认→提交→回读修订。可用 SQLite 起步，保留一个 CLI 用于开启 run、注入故障和查看事件。Temporal 用来对照历史重放与 Activity 的边界。作品展示时把本地故障注入结果、对真实模型的评测结果和生产方案分别标明。

最终留四样面试材料。

1. 一张时序图，包含 Agent loop、审批、领域写入和 worker 恢复。
2. 一个可复现命令，制造「领域提交成功、回执尚未被运行时记录」的故障。
3. 一份同一数据集的两版本评测报告，附可定位的 trace 和一次失败发布的证据。
4. 一页设计决策，解释幂等键的作用域、工具权限、修订冲突后的处理、版本回滚范围和当前规模假设。

## 模拟面试题

这些题按截图工作职责设计。

| 面试题 | 回答时应讲清楚 |
| --- | --- |
| 哪些步骤允许模型自主决定？什么时候应该采用固定工作流？ | 任务的不确定性、成本与可复现性。把停止条件、预算、授权和写入事务放在可测试的边界上。 |
| Worker 在设计提交成功但收到应答之前崩溃。重试怎么保证只产生一个新修订？ | 稳定操作 ID、领域侧原子保存写入与回执、重复请求返回原回执。同键异参拒绝。外部系统缺乏去重能力时需要查证或对账。 |
| 旧 worker 租约过期，新 worker 接手后，旧 worker 又活过来怎么办？ | 租约解释当前所有权，generation 或 fencing token 约束过期执行者；说明在哪个写入边界校验。 |
| SSE 断了，但任务继续跑了。前端如何重连？ | 持久化事件序号、游标、回放与去重。讲清历史保留窗口过期后的快照恢复，以及客户端怎样判断已提交。 |
| 上下文 checkpoint 和运行时 checkpoint 各保存什么？ | 前者保存已覆盖消息、摘要和证据指针；后者标记执行进度和已完成副作用。举一个摘要恢复成功、运行却仍可能重复提交的例子。 |
| 用户批准了提案，但执行前设计已经被别人改了，怎么处理？ | 授权绑定提案与基准版本，执行时用 CAS 检查。发生冲突后重新预览，并为改变后的动作重新审批。 |
| MCP 工具返回要求读取另一个 workspace 的文件，模型照做了怎么办？ | 工具输出按不可信数据处理。资源访问由服务端鉴权与执行边界控制，记录拒绝事件，并增加隔离回归用例。 |
| 新 Prompt 看起来更会回答，但重复提交增加了。你怎么决定是否发布？ | 用最终系统状态做断言，固定版本与数据集，重复运行对非确定性建基线。重复写入触发硬门禁，再定位工具调用和运行时 trace。 |
| 如何同时支持托管 Runtime 和外部 Runtime？ | 共享版本、策略与事件协议，明确外部运行时需要回报的事实。解释如何隔离租户、识别在途版本与验证外部执行结果。 |
| 编码题：实现一个最多并发 N、支持取消的异步工具执行器。如何测试？ | 并发上限、任务失败、取消传播、开始前取消与进行中取消，结果顺序及资源清理。 |

用两分钟回答第一轮，每题补一个失败时序和一条可自动化断言。答不清楚的地方就是下一次实践的起点。

## 第一晚的 90 分钟

1. 15 分钟：从 BeamJoin 接口文档画出读修订、预览、审批、提交、回读五步。
2. 20 分钟：读 Temporal 的 Workflow Execution 与 Activity Definition，标出每个崩溃点之后需要的持久状态。
3. 40 分钟：做一个有唯一操作 ID 的本地提交 fixture。提交后立即退出进程，通过同一个操作 ID 重试。
4. 15 分钟：验证两次请求返回同一个修订 ID，数据库只增加一个修订。给模拟面试第二题录一遍口述，记录哪里还缺证据。

当前进度为计划完成。首个练习从提交落库后的故障恢复开始，再按结果决定运行时部分的深度。
