# 当前报告生产流程与阻塞点（2026-09-11）

以当前实现和 retry-10 最后持久化记录为准。本轮按用户要求只验收接口与落库数据，网页由用户自行检查。

流程：用户问题与附件 → Backend 准入和权限冻结 → Run/Outbox 执行 → ML 中 Pi 通用 Agent 循环 → 读取 SEC/PDF → 登记字段证据 → 确定性计算 → 模型产出结构化报告 → 编译段落与引用 → Backend check-draft → 原文完整性验证 → 独立模型事实/编辑审查 → 通过则持久化 checkedCandidate → 原子写入报告版本 → 网页读取与引用定位。

首次审查拒绝时，返回具体 blockId/inputPointer 和修改原因给原 Agent，再补证据、计算或修订。检查点贯穿执行，包括消息、证据、计算、工具意图/结果、预算；不等同于已交付报告。显式重试继承已授权且重新核验的原文证据与计算，不继承已通过审查的结论。

当前 SEC 工具使用发现、BM25 与标题/短语匹配、表格导航和字段登记；PDF 使用已冻结解析版本的页/字段读取。不能将当前实现描述为已经上线完整 Embedding+Hybrid+RRF+Rerank 管线。

retry-10：初次报告完成原文验证并进入独立审查，返回 11 项事实或覆盖问题，主要是计算未绑定和表格字段缺引用。随后补至 62 条证据、13 项计算；修订稿第二次 submit_report 意图已保存，但没有完成结果。最后真实检查点 sequence=43、5942743 字节，checkedCandidate=false，reportVersionId=null，只保留初始化版本1。

已确认失败边界：修订稿提交后的执行/回调链，ML 执行未返回成功 HTTP 回执，Backend 记 research execution did not acknowledge completion。当前错误转换层把具体异常压成通用 503；不能据此断定是超时、大小限制或模型问题。尚未定位具体内层异常，不继续盲目付费重试。

下一步优先补齐不含原文/密钥的服务端错误分类与 Run/操作关联，并对保存的 submit_report 参数做离线回放；定位后只恢复报告提交/检查，不重新检索或解析。产品侧应把阶段、失败原因和可恢复入口暴露为数据。完整证据长期独立存储、执行状态尽量传引用是后续减重方向，不列作已实现。

验证环境是本地 Backend/ML、真实模型与 GCS、本地隔离 MySQL。该结果不能证明当前云端产品已完成部署或报告已可用。
