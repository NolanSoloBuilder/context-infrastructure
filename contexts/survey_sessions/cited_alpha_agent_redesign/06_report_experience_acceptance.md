# 报告体验细化与产物验收 v0.1

2026-09-10。对应L1产品体验、L2交互及验收规格。继承`03_product_experience_design.md`与`04_mvp_delivery_contract.md`，不替代、不缩小04的MVP范围。本轮只读取当前应用源码并补充设计，未修改应用、运行浏览器或重新发布。

## 1. 用户完成一次研究的定义

用户输入问题后，得到一份能够回答问题、解释依据、说明局限的自然报告。用户可以核对关键字段，理解并复算派生值，在当前研究上追加要求得到新版本。页面刷新、网络中断、运行失败不使用户误认旧版已更新，也不让同一任务重复执行。

高标准交付需要同时证明正文质量和证据链质量。格式正确、按钮能点、服务端状态为complete、单元测试通过分别只是局部证据。最终验收以真实任务生成的持久化报告、实际原文位置和后端运行记录共同判断。

## 2. 三类实际验收产物

以下是可直接指导模板和人工评审的结构样稿。`〈待取证：…〉`为设计占位符，禁止出现在正式交付正文中；必须替换为有出处的事实或明确的无法回答说明。本文件不填入未经本轮重新核验的金融数字，也不在验收提示中预先给模型正确答案。

### A. 短事实核验

验收请求示例：

> 请核对Tesla 2024财年的总营收，使用官方年报，说明币种、单位和口径，附可定位的原文引用。只回答这个问题。

产物样稿：

**Tesla 2024财年总营收核验**

Tesla该财年的合并总营收为〈待取证：金额〉〈币种及单位〉。该数值来自〈年报原始指标名〉，对应期间为〈起止日期〉。[来源入口]

这里采用合并总营收口径。〈仅在存在混淆风险时说明：汽车分部收入/营收成本为何不能替代该指标。〉

取证不成功时替换为：“目前取得的材料不能支持该年度的合并总营收；现有材料仅覆盖〈实际范围〉。本次无法给出该数字。”不得用另一年度、分部或成本数字补齐。

验收重点：答案出现在首屏；最多按需要补口径段；没有估值、情景表、冻结Task、事实账本或重复摘要。点击金额旁引用能够看到原表的指标行、年度列及单位。

### B. 完整公司财报分析

验收请求示例：

> 分析Tesla 2024财年业绩，解释收入、利润和现金流的变化，重点看汽车及储能业务。给我一份可阅读的中文分析报告，关键数字能核对原文，增长率能查看计算。不需要估值。

产物样稿：

**Tesla 2024财年业绩分析：收入、盈利与现金流**

导语：〈用一段给出整体判断：哪些指标变化、最重要驱动、结论的主要限制〉。不得只说“以下将分析”。

**核心业绩及可比口径**

〈本期与可比期的收入、盈利、现金流事实，金额单位、合并口径及会计期间〉。对用户需要比较的数据采用可扫描的并列呈现；比率或变化值关联计算。不能把财年总额与单季度直接比较。利润类别写全，如营业利润、归母净利润，不只写利润。

**汽车业务：变化由什么驱动**

〈可验证的量、价、产品组合或成本证据〉如何影响〈相关指标〉。区分“管理层称”与“数据直接表明”；若无法做精确贡献分解，明确可支持的方向及不能量化的部分，不输出未经证实的贡献百分比。

**储能业务：增长及盈利的含义**

〈业务规模、收入/盈利证据〉及其与整体业绩的关系。比较必须保留业务口径，不能用装机量代替收入增长。

**利润与现金流：哪些变化可持续**

〈成本、费用、一次性因素、资本开支或营运资本证据〉。解释利润和现金为何可能不同，原因需要实际资料支持。

**结论、限制与后续观察**

〈回到用户问题的判断〉。保留真正会改变结论的资料局限及可证伪的观察项。可核验事实、分析判断和未来不确定性用自然措辞区分。

**资料和计算说明**

资料截止时间、会计口径、必要调整。完整原文与公式通过证据面板阅读，不把原始日志追加到正文。

验收重点：这是完整分析而非多个数字核验拼接；各段存在“事实→解释→业务含义”的联系；收入、盈利、现金流和两个指定业务均得到回答或明确缺口；无强制估值和无证据的投资建议。复杂表格若当前段落结构不能清晰表达，应扩充报告块类型，不能以实现方便为由删掉用户要比较的指标。

### C. 跨信源比较

验收请求示例：

> 比较官方年报与另一份已授权材料对同一业务指标的说法。核对主体、期间、单位和口径是否一致，解释差异；不能判断时保留分歧，并分别提供原文位置。

第二来源必须实际获取，不由模型回忆生成。MVP覆盖两种来源的持久化材料，例如官方网页年报与用户上传PDF/表格；同一网页两个相邻段落不算第二信源，同一文件的两种渲染不算独立来源。

产物样稿：

**〈指标〉的跨来源核对**

结论先行：两份资料〈一致/表面不同但口径不同/同口径冲突/尚不可比〉。〈最重要理由〉。[来源A][来源B]

**各来源实际说了什么**

来源A：〈机构与文件、发布日期、指标、期间、单位、原文值〉。[A字段]

来源B：〈同样字段，缺项显式标注〉。[B字段]

**差异来自哪里**

〈期间错位、口径差别、单位换算、修订或真实冲突〉。换算必须显示公式和输入；只有证据支持时才能判断原因。资料更新时间较新不能单独证明新值更正确。

**当前可以采用的结论**

〈采用依据及使用范围〉，或者明确：“两项证据在已知相同口径下仍冲突，现有材料不足以判定哪项正确。”保留两条原文，不用排序分数裁决事实。

验收重点：能分别点击两个冻结原文、定位相应字段；冲突不得被检索去重丢失；至少一项实际派生计算可复算。第三方陈述的分析立场要标明归属。

## 3. MVP与后续边界

| MVP必须完成 | 后续扩展，可明确不包含在本次交付 |

| 两种来源真实快照、哈希和字段定位 | 所有网页/PDF/API/Excel/XBRL格式全覆盖 |
| 至少一个派生值的公式、输入证据和复算 | 任意公式、递归计算图、任意代码执行 |
| 自主多步工具调用、实际模型生成及修订 | 多Agent并发研究、通用插件平台 |
| 同一研究追加要求形成新版本，旧版可读 | 富文本直接编辑与逐字协作 |
| 刷新恢复、明确失败、版本与引用不串读 | 无限制后台长期监控 |
| 可见正文与复制/下载一致，来源解释完整 | PDF/DOCX复杂排版、公开分享新schema |
| 正式发布及真实Chrome验收 | 移动端Workspace、全局流量放量 |

03中的直接编辑是长期形态，MVP通过研究对话修订版本。公开分享目前禁止新schema是明确能力边界，不能显示可点击但无法正确读取的入口。上述后续项不允许用来豁免04任何P/R/E/D/Q/O项。

## 4. 交互验收脚本

### J1 提问到报告

进入真实登录工作区，提交A/B/C请求之一。确认运行使用新通用路径，观察真实工具调用，结果保存到当前工作区。阅读首屏后应能够概括答案、关键依据和限制。对照用户问题逐项审核，记录报告versionId、runId和完成时间。

通过证据：实际报告正文、后台实际工具轨迹、版本记录。失败例：只有计划或源材料列表；模板强塞无关章节；没有真实模型调用。

### J2 点击原文并返回报告

点击某个数字旁的引用，面板显示相关来源标题、逐字摘录、字段定位和口径。点击查看原文位置，打开宿主验证的快照，不接受页面传入任意locator。核对指标行、期间列、单位、脚注及PDF页/HTML位置。关闭查看器后应回到原报告附近；键盘焦点应回到触发入口。

通过证据：Chrome中完整点击和字段回读、相应snapshotId/hash、服务端owner与版本限定解析。失败例：只打开网站首页；在相同数字多处出现时高亮错误行；界面声称字段级而实际仅文档级；返回丢掉阅读位置。

### J3 从派生值到输入

点击增长率等派生值的引用。先看公式、结果、精度与单位，再逐一查看输入值和原文。用记录的原始小数及舍入规则独立复算，不从报告里反推输入。核对输入期间和单位可比较。

通过证据：计算记录、每项inputEvidenceId对应字段、独立复算结果、Chrome可读公式。失败例：只显示operation代码和结果；只有输入ID；用格式化后的已四舍五入数据反算；未显示其中一个输入来源。

### J4 续研和新版本

在已完成报告上追加真实要求，如“加入可比期变化并解释原因”。系统应关联当前产物与版本，启动新的run，完成后保存新版本。旧版本保持原文和原引用；新版本引用属于新冻结bundle。既有旧financial-report/v1报告和legacy报告仍可读取。

通过证据：至少两个不同版本、父版本/产物关系、每版引用解析、历史读取。失败例：重写旧版本、旧引用偷偷指向新原文、要求变化但重复交付上一稿、UI把同一内容另存即当作完成续研。

### J5 刷新、断流与失败恢复

运行中刷新；SSE断流后继续观察服务端同一run；不提交第二次任务。任务完成后报告自动更新，刷新再次读取相同版本。另以可控故障验证失败与取消：旧报告保留，状态说明本次未完成；重试仅由明确动作触发。证据面板请求期间切换版本/工作区，迟到响应不得展示。

通过证据：刷新前后runId、数据库任务数量、持久化事件、页面状态、故障样本。失败例：断流即显示成功；自动POST重建run；失败覆盖旧版；旧来源响应进入新报告。

### J6 复制、导出与可访问性

复制/下载当前报告，比较标题、所有正文段落、引用编号和计算。纯计算引用也要包含公式与各输入原文，混合引用对重复输入去重。窄屏阅读长报告时正文不横向溢出，长原文/表格在内部滚动。键盘可到达引用、关闭及重试；loading有可读状态，失败有恢复动作。

通过证据：实际下载文件和可见版本一致、Chrome桌面/窄屏回读、键盘路径。失败例：导出旧documentContent、只导内部ID、隐藏失败来源、先报完整交付后正文仍有待填占位符。

## 5. 页面与服务落点及当前缺口

以下是本轮读取的源码状态，不等于已上线。

| 落点 | 当前行为 | MVP仍需证明或补齐 |
|---|---|---|
| `AppWorkspaceDetailPage.tsx` | research marker优先路由；documentJson/provenance投影；只读/复制下载；旧报告路径保留 | 新运行入口、续研对应新版本、真实恢复和运行成功后的当前版本更新 |
| `ResearchReportDocumentView.tsx` | 自然标题、摘要、段落；稳定全篇编号；文本安全渲染 | 段落级citation尚未精细到句内数字；来源名称的可理解性；长完整研报视觉验收 |
| `ResearchReportArtifactView.tsx` | 来源面板、scope防漂移、loading/error/retry；onOpenEvidence可选 | 当前页面未传原文callback；点击之后仍不能真实打开原文；面板显示计算名称与结果，尚缺明确公式展示；关闭焦点返回待验证 |
| `services/research-reports.ts` | marker/guard、bundle正文一致性、版本限定来源GET、集合校验、公式及输入原文导出 | 服务端实际响应兼容；完整snapshot语义/权限来自Backend，不是Web guard保证 |
| `WorkspaceArtifactReferenceProvider` / `DocumentReferenceViewer` | 既有同页HTML/PDF定位与权限分域 | 新研究引用需要宿主固定snapshot/locator的解析入口；不能复用可被请求方覆盖locator的旧行为 |
| `useWorkspaceRunObservation` / stream recovery | 旧路径已有服务端回读与恢复机制 | 新研究路径必须真实复用且端到端验证，不仅靠旧测试 |
| `research-report/v1` | 当前只允许paragraph block | 完整财报/比较需要高可读指标呈现；若扩table须同步Backend/ML/Web合同与导出，不能在text塞Markdown表格后声称结构表格已支持 |

版本合同：`ArtifactVersion.documentJson`为纯`research-report/v1`正文；`ArtifactVersion.provenance`为冻结`research-report-bundle/v1`，含document/citations/evidence/calculations/contentHash。Web只读取同版一致bundle。用户正文和原文的快照定位要分开，report blockId不能替代source locator。

来源接口：`GET /api/v1/workspaces/{workspaceId}/artifacts/{artifactId}/versions/{version}/research-citations/{citationId}` 返回`{citation,evidence,calculations}`。来源和计算集合必须恰好覆盖本引用及其计算输入；用户不传入自定义locator。原文源文件/HTML读取需要同样限定该版本的可信evidence身份；具体端点由Backend接口实现冻结后登记，本文不猜测已存在接口。
