# Agent 可操作的铝构件创意平台：首版产品方案

日期：2026-09-23。状态：可实施规格；与[技术方案](2026_09_23_agent_native_aluminum_platform_technical_architecture.md)配套。本文替代同目录《AI 铝构件创意平台：编辑器与 Agent 协作方案（讨论稿）》中的首版范围和未决问题。

实施范围更新（2026-09-24）：当前可运行版本先验证“设计任务 → 候选方案 → 规则审阅 → 修订/待处理草稿”主流程。范围、已实现内容与后续顺序见独立仓库内 [PRODUCT.md](https://github.com/NolanSoloBuilder/agent-native-aluminum-platform/blob/main/PRODUCT.md)；下文保留长期产品目标。

## 1. 已确定的产品决策

| 议题 | 决策 |
| --- | --- |
| 物料来源 | 嘉立创 FA 是首版**示例供应商**，不是平台主数据或永久依赖。设计模型使用平台自有规格和几何；供应商 SKU 通过显式映射绑定。以后由市场需求决定加入哪些供应商和物料。 |
| 两条设计路径 | 首版同时交付参数模板改型和从空白开始的自由定制，两条路径共享同一设计文档、校验和导出。 |
| Agent | Agent 是首版核心交互。内置 Agent 和外部 Codex/Claude 等客户端通过同一命令服务读、预览、修改项目；Agent 能打开对应网页，让用户在画布中看到和接续编辑。 |
| Demo | 现有 `adhoc_jobs/aluminum_editor_demo/` 可整个丢弃。架构和数据契约从首版建立，不以现有组件为边界。 |
| 用户创意 | 首版包括发布可复用设计、浏览、复制改作和来源链；社交推荐与交易网络以后扩展。 |

我们要交付的是**从需求到可持续修改的装配方案**。用户每次手工或 Agent 改动都应保持 3D、参数、连接、加工和材料清单的一致性。供应商信息作为采购映射，而非覆盖用户的设计意图。

### 需求输入与 Agent 的判断边界

用户可以在对话中输入目标，也可以直接填表或从画布选中对象。系统把条件分为**硬约束**（空间上限、必需净空、设备外形、必须保留的连接/面板）与**偏好**（颜色、拆装便利、预算、供应商）。每条条件记录数值、单位、来源和“已确认/待确认”；Agent 不能把自己补猜的承载重量或加工能力写成已确认。硬约束缺失且会改变结构时，Agent 先追问；可合理默认的样式选择必须在提案中显示。没有有效供应商报价时，“预算优先”只能作为材料用量偏好，不能承诺最终价格。

从零生成先输出一个能在画布继续编辑的构件图，并解释为何选用这些型材、连接和尺寸。Agent 随后仍通过同一套命令做局部增删、整体改型和材料替换；生成不是一次性图片或不可编辑的 3D 文件。

### 首版目标用户与设计对象

优先用户是做设备支架、工作台、储物架和小型柜体的 DIY 用户、创客和小型工作室。首版设计对象是直线型材、常见连接件、平面板材及其装配；支持任意数量和排列的这些构件。自由定制指可从空白添加、移动、旋转、连接、删改构件，并让 Agent 针对任意选区生成修改。曲面、复杂钣金折弯和任意 CNC 自由形体另属不同制造链，不纳入首版。

“能画出来”和“可按已知规则交付制造”分别显示。首版自动确认的制造规则只覆盖已录入的型材、90° 常用连接、直切和少量明确验证的加工；其它连接/角度仍可作为设计草稿表达，但给出未解析项，不标记为可询价。整件承载、防倾倒、振动及接头刚度不做安全认证。嘉立创公开的[工艺参数](https://xc.jlcfa.com/process)说明同样标称为 20 系列的型材也可能采用不同孔径和螺纹，不能凭“2020”字符串推断适配。

| 连接设置 | 外部 Agent 授权、项目范围和权限 | 给客户端只读/提案/编辑/导出权限，查看与撤销授权 |
| 作品详情 | 3D 预览、关键尺寸、材料与规则版本、说明、作者/许可、版本来源 | 浏览、收藏、复制改作、上传装配照片/反馈（基本形式） |

左侧材料分类参考[嘉立创 FA](https://xc.jlcfa.com/)的型材/连接/加工/面板组织；画布交互参考[乐玩 DIY 编辑器](https://www.lewandiy.com/editor)可见的变换、吸附、对齐和材料清单；框架/箱体构型器和实体树参考[IdeaBuilder 官方功能](https://8020.net/ideabuilder)。这些是功能需求的来源，不将厂商公开控件视为已验证的完整工程行为。具体证据边界见[现有编辑器比较](aluminum_editor_capability_comparison_20260923.md)。

## 3. 四条首版主流程

**A. 模板改型。** 用户在模板页看到适用场景、参数范围、已验证物料版本和设计状态；复制到私人项目后修改宽深高，或对 Agent 说“宽度改为 850 mm，下层净空至少 300 mm，面板保留”。Agent 读取项目/选区/物料条件，补问缺失的硬约束，形成变更预览。用户看到画布高亮、尺寸、连接、加工和 BOM 差异，再应用。与模板生成件关联的局部手工修改被保留或明确报告冲突；不能悄悄重建整个框架。

**B. 自由定制。** 用户从空白项目加入单根型材、复制并吸附为结构，添加连接件或让 Agent “补一根中部横梁并让支架保持对称”。用户能直接修改任一构件；Agent 也能对选区批量改规格。参数组件和自由构件可共存在一个项目中。无法由已支持的连接/工艺规则覆盖的部位在画布和校验清单中明确标注，仍可保存草稿、继续编辑。

**C. 外部 Agent。** 用户在设置中授权某外部客户端访问指定项目。Agent 可列出项目、读概要和实体、查询材料，提交修改预览；`open_editor` 返回同一项目的网页链接，宿主支持浏览器面板时可在 Agent 内打开。用户在编辑器中看到提案和实时变化，也能继续手动编辑。旧修订的提案遇到人工新修改时失效，Agent 必须重读后重新预览。ChatCut 的[官方 Agent Plugin 文档](https://chatcut.io/docs/agent-plugin)证实“外部 Agent 工具修改同一项目 + Browser 面板展示编辑器”这一交互形态；我们的事务和命令设计属于本平台方案，不推断为 ChatCut 的内部实现。

**D. 分享与改作。** 用户选择某一设计修订发布，填写用途、尺寸、装配说明、设计许可、素材授权和实物照片。公开页显示该不可变版本的 3D/参数/BOM 摘要及适用规则版本。获准改作的作品可 fork 为私人项目，后续发布保留 `forkOfPublicationId`；原作者之后修改不会暗中改变别人的已复制设计。私有项目及未获授权的第三方资源不可误发布。

## 4. 关键状态与交互反馈

设计就绪度按三项分别显示，避免“几何规则通过”被误读成“某供应商能加工”：

1. `designRules = pass | incomplete | invalid`：平台的几何、尺寸与连接规则结果。
2. `supplierDfm = not_selected | pass | incomplete | invalid`：指定供应商及其工艺版本能否加工当前设计。
3. `procurementMapping = complete | incomplete`：切料、加工与五金清单的必要条目能否映射到具体商品。

只有三项分别达到 `pass/pass/complete`，并且绑定同一固定修订和供应商时，页面才显示“可生成询价包”。这仍表示通过**已覆盖的规则**，不构成整件安全认证。报价是第四条独立状态轴：`NO_QUOTE`、`QUOTE_CURRENT`、`QUOTE_STALE`。首版只有用户附加合法取得的外部报价时才显示报价状态；报价必须绑定设计修订、映射版本和有效期，没有官方接口时页面不出现实时价格承诺。

Agent 的每个提案显示：原始需求、目标修订、作用范围、新增/删除/替换构件、外形/净空变化、连接/加工变化、BOM 差异、规则错误和风险提示。红色错误阻断“通过当前规则”的标记；黄色待复核项允许保留草稿并进入人工判断。无论由画布还是 Agent 产生，同一问题指向相同实体 ID 和规则编号。

例如用户要求“宽度改为 850 mm，保留下层 300 mm 净空”：Agent 面板依次呈现读取的项目修订、使用的型材/规则版本、拟执行的 `SetAssemblyParameter` 等命令、预览中改变的梁和面板、BOM 与加工差异、未满足的约束、最终应用的修订号。用户可以点任一步定位到画布实体，也可以取消提案。这条可见过程是 Agent 化产品体验的一部分。

外部 Agent 默认获得“读取 + 提案”授权。用户可给指定客户端、指定项目追加编辑权限，使其直接提交低风险可撤销编辑；发布、请求报价或未来下单是独立权限和显式确认。用户随时可撤销客户端授权。浏览器 URL 只携带项目与提案 ID，不携带访问令牌。

## 5. 产品验收标准

| 场景 | 必须观察到的结果 |
| --- | --- |
| 模板任务 | 将 `900×500×750 mm` 框架改为 `850×450×900 mm`、四角换规格、下层保留 300 mm 净空和原面板；尺寸、型材切长、连接/加工、BOM 同一修订一致。局部手工 override 不被静默抹掉。 |
| 空白任务 | 从空白通过手工或 Agent 添加多根型材和面板，连接为可保存项目；非 90° 或未覆盖工艺仍能表达为草稿，并出现明确的实体级未解析项。 |
| 外部 Agent | 用 Codex 和至少另一种 MCP 客户端完成读 → 预览 → 网页查看 → 提交 → 人工改动 → Agent 重新读取；撤销后设计恢复到预期修订。 |
| 供应商替换 | 对同一中立设计换一个供应商候选，系统列出几何/槽口/加工兼容差异，不能只因规格名相同就自动替换；无匹配物料保留需求与未映射 BOM。 |
| 并发与失败 | 预览不改变项目修订；重复提交幂等；Agent 以旧修订提交得到冲突和当前版本；失效的物料或报价给出可操作提示。 |
| 分享 | 公开的是经用户确认的不可变修订；fork 保留许可和来源，能从 fork 继续编辑和重新校验。 |

技术验收采用 10–20 个真实桌、架、柜需求，记录从需求到规则已检查方案的完成率、补问次数、人工修正次数、BOM 差错、Agent 提案接受率和因校验被阻断的原因。先建立基线，再定增长目标；不凭厂商宣传或 Demo 截图设定完成率。

## 6. 交付边界与数据来源

嘉立创 FA 的[服务条款](https://www.jlcfa.com/text/protocol)（亦见[嘉立创集团帮助中心版本](https://www.jlc.com/portal/server_guide_36741.html)）将产品目录、文字、数据和图片列为受保护内容，并对网站信息的用途作出限制。首版公开示例使用自己绘制、验证的中立截面与连接模型；嘉立创映射只有在取得许可，或用户为其询价/订货逐单提供必要信息时才启用。批量引入其 SKU、CAD、图片或价格需要明确授权或合作依据，并记录来源与许可。供应商参数和价格可能更新，设计与报价应独立留版本。

首版不承诺：自动向嘉立创下单、官方实时价格、整件安全认证、任意 CAD 几何、所有面板/门/抽屉工艺、复制竞品页面和资产。是否进入采购闭环由可用接口和市场需求决定；平台的核心是供应商可替换的设计与 Agent 操作能力。
