# 中国地铁打字：根源站功能差距与登录排行榜方案

日期：2026-07-14

## 结论

当前版本已经具备可玩的单局体验，但还不是一个能长期回访的产品。下一阶段不应先复制更多模式，而应先做成最短的留存闭环：

> 游客立即开玩 → 完成标准化挑战 → 看到成绩与预估名次 → Google 登录认领成绩 → 进入日榜/周榜 → 次日回来刷新名次。

`densyatyping.com` 的公开说明显示，其 Google 登录主要承担云端存档与跨设备同步；截至本次调研，在公开首页、帮助页和 sitemap 中没有发现公开排行榜入口。因此“登录上榜”可以成为中国版本的明确差异化，而不是机械照搬。

Codex 的 Chrome 与内置浏览器插件均在初始化时出现 `Cannot redefine property: process`，无法完成要求截图的正式视觉审计。本报告是基于根源站公开服务端渲染页面、帮助与隐私说明，以及本项目当前代码完成的功能级对比，不包含截图层面的视觉与交互结论。

## 排行榜产品定义

### 第一版只做一个公平主榜

主入口为“每日挑战”，而不是把所有自由选线成绩混成一个榜：

- 每天固定城市、线路、区间、方向与站点顺序，所有玩家题目一致。
- 简体中文与拼音分成两个榜；中文使用 CPM，拼音使用 WPM，禁止直接互比。
- 30 秒为统一时长。
- 主分数由服务端计算：`速度 × 准确率²`。
- 同分依次比较：通过站数、错误数更少、完成时间更早。
- 展示日榜、周榜和个人最佳；全站历史总榜后置，避免早期玩家永久占位。

自由选线与全线模式可以记录个人最佳，但首版不上统一总榜。第二阶段再增加“线路榜”，其榜单键必须包含：城市、线路、区间、方向、输入方式与数据版本。

### 登录时机

不设置开局登录墙。推荐流程：

1. 游客直接开始每日挑战。
2. 结束页立即展示分数、个人设备最佳和预估名次。
3. 未登录用户看到“使用 Google 登录并认领本次成绩”。
4. OAuth 跳转前保存待认领局；回调成功后一次性提交。
5. 已登录用户自动提交，并显示“第 N 名 / 超过 N% 玩家”。
6. 榜单只展示昵称与可选头像，永不展示邮箱。

这比首页强制登录更有转化理由：用户已经投入一次游戏，登录得到的是明确结果，而不是抽象承诺。

## 技术架构建议

沿用现有 Cloudflare Worker，不再引入第二套业务数据库：

- Cloudflare Worker：静态资源、`/api/*` 排行榜接口、`/api/auth/*` 登录接口。
- Cloudflare D1：用户、会话、挑战、游戏记录和榜单最佳成绩。
- Better Auth：Google OAuth 与会话；通过 Drizzle SQLite adapter 连接 D1。
- Turnstile：只在可疑提交或高频请求时触发，正常玩家无感。
- Rate Limiting：限制开局令牌和成绩提交频率。

当前官方资料确认 D1 可直接由 Worker 查询，带 SQLite 语义、备份与按查询/存储计费；Better Auth 提供 Google 登录、Drizzle SQLite adapter 和 Cloudflare Workers handler。该组合让认证、业务数据与榜单查询留在同一个 Worker/D1 边界内。

建议数据模型：

- `users`：认证主体、公开昵称、头像、公开榜单开关、创建时间。
- `daily_challenges`：日期、城市、线路、区间、方向、输入方式、数据版本、题目摘要。
- `run_sessions`：一次性 nonce、服务端开始时间、过期时间、挑战 ID、可选用户 ID。
- `game_runs`：速度、准确率、站数、错误数、服务端分数、有效性状态、风控原因。
- `leaderboard_entries`：每个用户在每个榜单键下的最佳 `game_run`；唯一键为 `(board_key, user_id)`。

榜单索引至少覆盖 `(board_key, score DESC, achieved_at ASC)`，避免每次读取全表扫描。

## 成绩可信度

浏览器游戏无法做到客户端绝对可信，第一版目标应是“挡住低成本作弊、保留人工处置证据”，而不是假装完全防作弊：

- 开局必须从服务端领取一次性 `run_session`，服务端记录开始时间。
- 服务端掌握挑战题目与数据版本，不接受客户端自定义路线。
- 客户端提交计数与按键时间序列摘要，分数由服务端重新计算。
- 拒绝已使用 nonce、过期局、时长不符、题目版本不符和超出生理阈值的成绩。
- 对零抖动输入、重复时间序列、异常高速度标记 `review`，不立即进入公开榜。
- 高频提交使用速率限制；可疑提交再触发 Turnstile Siteverify。
- 保留申诉、隐藏成绩与封禁入口，但首版不做复杂设备指纹。

## 实施顺序

### P0：登录上榜闭环

1. 固化每日挑战和服务端计分规则。
2. Worker API、D1 migration、Google 登录。
3. 结果页“认领成绩”、榜单页和个人名次。
4. 一次性开局令牌、基础异常阈值、限流。
5. 隐私政策、服务条款、账号与数据删除入口。

### P1：让玩家回来

- 周榜、连续练习天数、个人趋势、线路个人最佳。
- 成绩分享卡、刷新个人最佳提示、好友链接。
- 音效、到站反馈、键盘教学与拼音容错增强。

### P2：长期成长

- 城市探索、换乘图、车站/线路解锁。
- 徽章与收集册。
- 随机、指定区间与跨线挑战。

### P3：社交玩法

- 好友榜、学校/班级榜。
- 实时或异步对战。

## 本次产品判断

下一步应该直接做 P0“每日挑战 + Google 登录 + 日/周榜”，不要先扩充冒险模式。排行榜先提供清晰、可分享、可重复挑战的竞争理由；探索与收集随后用于加深留存。这个顺序能最快验证用户是否愿意因为成绩和名次再次回来。
