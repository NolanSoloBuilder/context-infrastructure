# 底层逻辑：

1. **信源池 (Source Pool)**  
 → 它会从多种外部源抓取内容（如 Twitter、新闻、播客、newsletter、学术论文等）。  
 每个源通常有不同的采集管道（RSSHub、API、网页爬虫、第三方聚合器）。
2. **模块 (Modules)**  
 → 每个模块定义一个“关注维度”，比如 *Macro Signal* 或 *AI Stack Evolution*。  
 每个模块会声明：

   - 信源权重（哪些来源更重要）
   - 内容过滤器（主题关键词）
   - 输出形式（比如 “headline + implications”）
3. **内容过滤 & 语义聚类**  
 → 系统通过 embedding 或 keyword filters 对抓到的原始内容进行筛选。  
 例如：意味着只保留与这些主题语义相近的信号。

 （内部可能用 OpenAI Embeddings、Cohere Classify、或自建 keyword rules 实现）

1. **信号打分 (Scoring Logic)**  
 → 每条候选内容按以下维度计算一个综合得分：

`score = 0.3*freshness + 0.4*relevance + 0.2*source_authority + 0.1*social_signal`

这些分数来源可能是：

- Freshness：发布时间衰减函数
- Relevance：语义相似度或 keyword 命中率
- Source authority：来源白名单权重（如 Stratechery > random blog）
- Social signal：推特互动、转发数、Hacker News 排名等

1. **渲染层 (Rendering Rules)**  
 → 将打分最高的信号转为“卡片（card）”，按模块优先级与样式生成简报：

`style: "assertion-evidence-insight"
``card_limit_per_module: 2`

最终输出就是一个信息流仪表盘或日报（Pulse feed）。



## 抓取逻辑：

### 1️⃣ 用户 Context 定义

- 用户订阅的类别（News、Newsletter、Podcast、Article…）
- 用户关注的主题/关键词（AI、创业、区块链、健康等）
- 用户行为数据（点击、收藏、浏览时长）
- 历史互动数据（点赞、分享、评论）

---

### 2️⃣ 榜单 Alignment 原则

- **内容相关性**：榜单条目必须和用户兴趣标签匹配
- **新鲜度优先**：动态更新每日/每周热门内容
- **多来源覆盖**：中英文混合榜单，保证信息全面
- **权重排序**：结合用户偏好 + 热度 + 信源质量

---

### 3️⃣ 实现方式示例

- **基础榜单抓取**：保持当前扩展版榜单列表（RSS/API/网页抓取）

1. **关键词过滤/匹配**：抓取后，按用户兴趣关键词过滤条目
2. **兴趣画像打分**：每条内容打分（匹配度、热度、可信度）
3. **动态排序 & 推荐**：生成每日 Pulse 推荐列表，确保内容与用户 context 对齐



# 信源策略：



## 🔍 深层逻辑：为什么“信源”成了竞争壁垒

### 1️⃣ **数据规模 ≠ 训练数据**

AI 搜索的关键不只是训练模型，而是 **实时语料的摄取能力 (fresh web coverage)**。  
 Google 拥有：

- 自己的 global crawler 网络；
- 每天几十亿站点主动“feed”；
- 完整的索引与 ranking 基础设施。

这意味着：

> Google 拥有“世界上最实时、最完整的信息图谱”，是搜索产品的天然壁垒。

---

### 2️⃣ **Perplexity / OpenAI 面临的成本曲线**

它们的瓶颈不在模型，而在：

- 🌐 **爬取 (Crawling) 成本**：带宽 + 反爬机制 + 法律边界；
- 🧠 **解析 (Parsing) 成本**：网页结构化成 retrievable chunk；
- 💾 **索引 (Indexing) 成本**：embedding + storage + retrieval latency；
- ⚖️ **合规 (Copyright)**：无许可抓取风险。

所以现在的策略一般是：

> “有限信源 + 高价值压缩 + 模型语义搜索”。

也就是只抓取可公开的、高信噪比数据源，例如：

- Wikipedia / Common Crawl / Arxiv / News API / Stack Overflow / Reddit
- 再通过语义索引 (vector DB) 提高检索命中率。

---

### 3️⃣ **xAI 的另类信源优势**

xAI 拿到的是：

- Twitter/X 全量流（firehose）
- 与 Tesla / SpaceX 等内部数据可能未来打通

这类流信号不是传统网页，而是 **social event graph**。  
 → 实时性极强（秒级）  
 → 但覆盖面窄（社交主导，缺乏结构化知识）

xAI 的策略更像：

> “把世界的即时对话层变成信号输入”。

---

### 4️⃣ **Google 的隐形杀手锏：push-based indexing**

- 约一半网页不是自己爬到的，而是网站主动“推送”的。  
 （Amazon 新上架商品 / YouTube 新视频 / Twitter 新 tweet）
- 这使得它不再依赖 crawler 的拉式模式。

→ 信源动态更新快、内容权威、成本低。
