## 邮件环境信号评估`email_env_for_`（per email）

（先判断是哪个语义环境？再判断每个tag里的权重？）

每封邮件先按 **Sender / Body / 行为 / 时间** 四个维度，分别给出对 3 类 object 的**环境强度（0–3）**，再合成一个该邮件对不同 object 的整体环境分，作为 **“这封邮件整体而言，对某一类 object 的最大可信度环境”**；  
后续在object 级别再看每个具体 topic/entity/source 在正文里的角色，只是在这个环境上再做一个 per-tag 的缩放。

---

#### 环境信号输出

统一用 0–3 档，方便实现：

- `0` = 没有环境信号（基本不能用来判断这个 object）
- `1` = 弱环境信号（可能相关，噪音多）
- `2` = 中等环境信号（有用，但不是特别强）
- `3` = 强环境信号（高度可信）

 **UserObjectRelation 里会用到的字段**：

- `object_type ∈ { "topic", "entity", "source" }`
- `relation_type ∈ { "subscribe", "follow", "use", "pay", "contact", "mentioned" }`
- `context ∈ {`` "work",`` "personal", "mixed", "unknown" }`
- `intent ∈ { "learn", "keep_up", "hobby", "unknown" }`
- `confidence ∈ [0,1]`（或者 0–3 档，概念一样，当成“强/中/弱”）
- `signal_count`（累计信号次数）



**从UserObjectRelation表中提取：**

用户「长期想跟着看的对象」是谁（topic / entity / source）；

- 这种关系是 **subscribe / follow / use / pay / contact** 的哪一种；
- 它主要发生在 **Gmail newsletter / Gmail 工作往来 / Twitter / Podcast / Blogs** 哪些渠道；
- 它的 **intent（learn / keep_up）** 和 **context（work / personal）** 是什么；
- 以及这个关系目前有多强（`confidence` + `last_seen_at`）。
- 上面几种合辑（Gmail Newsletter 总结、工作往来、延伸信息、领域态势、实体追随、Insights），本质上只是对这些关系的不同「切面」：

  - **按 source 维度切 → Gmail Newsletter 合辑**
  - **按 work context + entity 切 → 工作往来 & 延伸信息**
  - **按 topic follow + intent 切 → 领域态势 & Insights**
  - **按 entity follow/use/pay 切 → 实体追随**

#### **高热兴趣点判定方式**

判定对象： 收件箱中的所有邮件，包括但不限于订阅邮件、个人通信、交易通知等。

核心逻辑： 跨来源识别被广泛讨论和关注的议题，并排除系统自动更新的干扰。



1. 跨来源兴趣点提取与统计：

   - 从所有邮件的主题和正文中，提取公共的兴趣点。
   - 在设定的时间窗口内（如7天、14天、30天），进行两项核心统计：
   
     - 跨来源数： 该兴趣点出现在多少个不同的发件人/发件域的邮件中。
     - 总文档数： 包含该兴趣点的邮件总数。
2. 新域名出现提升兴趣点权重：

   - 识别新域名： 系统需要记录历史发件域名。对于一个兴趣点，如果其来源中包含一个在过去7天内首次出现的发件域名，则视为一个强有力的正向信号，显示这是用户当下正在关注的内容/执行的任务。
   - 提升权重：
   
     - 在计算该兴趣点的热度时，每出现一个新域名，就显著提升其权重（例如，在跨来源数上给予倍数加成，或直接增加一个高额权重分）。
     - 逻辑解释： 用户收到一个全新域名的订阅/订单确认邮件，极有可能意味着他近期主动进行了一次新的应用注册、服务购买或内容订阅。这个行为比单纯收到已有关注域名的邮件，更能体现其当前活跃和强烈的兴趣。
3. 识别与去重“自动更新”：

   - 识别： 识别由系统自动触发、内容重复或高度相似的邮件（如发件人为“noreply@”、主题为固定模板的周报、账单等）。
   - 去重与合并：
   
     - 对于识别出的自动更新邮件（如来自同一服务的每日状态更新），如果它们属于同一个会话或服务，则合并计算为一次有效出现，以避免单一服务的高频更新扭曲热度。
     - 注意： “新域名”邮件的权重提升，主要应用于首次出现的订阅或交易确认邮件。之后来自同一域名的例行自动更新（如周报），则按去重规则处理。
4. 标注“高热”：

   - 设定一个综合阈值，该阈值同时考量：
   
     - 加权后的跨来源数
     - 总有效文档数



核心逻辑： 订阅信号主要来自区分是否来自用户的主动订阅，降低注册账户时默认勾选或系统自动推送的泛阅读内容。排除广告，
