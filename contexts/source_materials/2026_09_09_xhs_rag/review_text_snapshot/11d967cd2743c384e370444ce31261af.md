## 一、RAG 评测的核心挑战

RAG（检索增强生成）系统由两个关键组件组成：**检索器**（从知识库获取相关上下文）和**生成器**（基于上下文合成答案）。这种两阶段设计带来了独特的评测挑战：

- 完美的生成器无法弥补检索遗漏必要信息的缺陷

- 完美的检索如果生成器产生幻觉（hallucination）也是徒劳

- 需要同时评估检索质量、生成质量，以及两个组件的协作效果

传统的文本生成指标如 **BLEU** 和 **ROUGE** 主要关注表面文本相似度，无法捕捉 RAG 应用的核心需求：

- **事实准确性**：回答是否基于检索到的证据

- **上下文相关性**：检索的文档是否与查询相关

- **信息完整性**：是否覆盖了查询所需的所有信息

## 二、主流开源 RAG 评测框架

### 1. RAGAS (RAG Assessment)

- **定位**：RAG 评测的事实标准（de facto standard）

- **特点**：支持无参考（reference-free）评测，使用 LLM 自动化评估

- **优势**：实验驱动，覆盖 RAG 系统、Agent 和经典 NLP 任务

- **GitHub**：[https://github.com/explodinggradients/ragas](https://github.com/explodinggradients/ragas)

### 2. DeepEval

- **定位**：开源 LLM 评测框架

- **特点**：Pytest 风格的测试，支持 Agentic 和 Chatbot 评测

- **优势**：功能全面，包含 RAGAS 的所有功能并有所扩展

### 3. TruLens

- **定位**：专注于 RAG 三元组（RAG Triad）评测

- **特点**：强调上下文相关性、忠实度和回答相关性

- **优势**：诊断性强，能精确定位系统故障点

## 三、RAGAS 核心指标详解

RAGAS 提供了一套专门针对 RAG 系统的评测指标，分为**检索质量**和**生成质量**两大类。

---

### 📊 生成质量指标

#### 1. 忠实度 (Faithfulness)

**定义**：衡量生成回答与检索上下文的事实一致性，检测幻觉问题。

**核心思想**：

- 将生成回答分解为多个独立声明（claims）

- 检查每个声明是否能从检索到的上下文中推导出来

- 计算受支持的声明比例

**计算公式**：

```plaintext
Faithfulness = 受上下文支持的声明数 / 总声明数
```

**示例**：

```plaintext
查询：法国的首都是什么？
生成回答：巴黎是法国的首都，也是欧洲最大的城市。
检索上下文：巴黎是法国的首都，是一座以艺术和文化闻名的城市。

分析：
- 声明1："巴黎是法国的首都" ✓ 受支持
- 声明2："巴黎是欧洲最大的城市" ✗ 不受支持（上下文中未提及）

Faithfulness = 1/2 = 0.5
```

**实现机制**：使用 LLM 进行两步处理：

1. **声明提取**：从回答中提取所有事实声明

2. **支持性验证**：判断每个声明是否能从上下文中推导

**取值范围**：0-1，分数越高表示幻觉越少。

---

#### 2. 回答相关性 (Answer Relevancy)

**定义**：评估生成回答与原始查询的相关程度。

**核心思想**：

- 从生成回答中反向生成多个问题

- 计算这些问题与原查询的语义相似度

- 相似度越高，说明回答越切题

**计算公式**：

```plaintext
Answer Relevancy = mean(生成的问题与原查询的相似度)
```

**示例**：

```plaintext
查询：法国的首都是什么？
生成回答：法国的首都是巴黎，以其艺术、文化和时尚闻名。

反向生成的问题：
- 法国的首都叫什么？（高相似度）
- 巴黎以什么著称？（中等相似度）
- 法国的首都是哪里？（高相似度）

平均相似度 ≈ 0.75-0.85
```

**实现机制**：

1. 使用 LLM 从回答中生成 N 个问题（默认 N=3）

2. 计算每个生成问题与原查询的余弦相似度

3. 取平均值

**取值范围**：0-1，分数越高表示回答越切题。

---

#### 3. 回答正确性 (Answer Correctness)

**定义**：综合评估回答的事实准确性和语义完整性，需要参考答案。

**核心思想**：

- 结合**语义相似度**和**事实重叠度**

- 语义相似度：回答与参考答案的嵌入向量相似度

- 事实重叠度：基于 TP/(TP+FP+FN) 的 F1 分数

**计算公式**：

```plaintext
Answer Correctness = w1 × 语义相似度 + w2 × 事实重叠度
```

（默认 w1=w2=0.5）

**示例**：

```plaintext
查询：法国的首都是什么？
参考答案：巴黎是法国的首都，是欧洲主要城市之一。
生成回答：巴黎是法国首都，以文化闻名。

语义相似度：0.85（语义接近）
事实重叠度：0.67（部分事实匹配）

Answer Correctness = 0.5×0.85 + 0.5×0.67 = 0.76
```

**实现机制**：

1. **语义相似度**：使用嵌入模型计算向量余弦相似度

2. **事实重叠度**：

- 从回答和参考答案中分别提取声明

- 分类为 TP（真阳性）、FP（假阳性）、FN（假阴性）

- 计算 F1 = TP/(TP + 0.5×(FP+FN))

**取值范围**：0-1，需要标准答案（ground truth）。

---

#### 4. 回答相似度 (Answer Semantic Similarity)

**定义**：衡量生成回答与参考答案的语义相似度，仅基于嵌入向量。

**核心思想**：

- 使用嵌入模型将回答和参考答案转换为向量

- 计算余弦相似度

- 捕捉语义层面的相似性，而非表面文本匹配

**计算公式**：

```plaintext
Answer Similarity = cosine_similarity(embed(回答), embed(参考答案))
```

**示例**：

```plaintext
参考答案：巴黎是法国首都，人口约220万。
生成回答：法国的首都是巴黎，是一座大城市。

嵌入向量相似度 ≈ 0.78
```

**特点**：

- 不需要分解为声明

- 对表述方式的差异更宽容

- 适合评估语义等价性

**取值范围**：0-1，需要标准答案。

---

### 🔍 检索质量指标

#### 5. 上下文精确率 (Context Precision)

**定义**：衡量检索到的上下文中，与回答问题相关的信息占比。

**核心思想**：

- 评估检索到的每个文档/片段是否包含回答问题所需的信息

- 关注"检索到的内容中有多少是有用的"

**计算公式**：

```plaintext
Context Precision@K = (前K个检索项中相关的数量) / K
```

**示例**：

```plaintext
查询：法国的首都是什么？
检索到 5 个文档片段：
1. 巴黎是法国的首都... ✓ 相关
2. 法国位于欧洲西部... ✗ 不相关
3. 巴黎以埃菲尔铁塔闻名... ✗ 不相关（未提及首都）
4. 法国首都是巴黎，人口220万... ✓ 相关
5. 法国是欧盟成员国... ✗ 不相关

Context Precision@5 = 2/5 = 0.4
```

**实现机制**：使用 LLM 判断每个检索片段是否包含回答问题所需的信息。

**取值范围**：0-1，需要标准答案。

---

#### 6. 上下文召回率 (Context Recall)

**定义**：衡量检索到的上下文是否覆盖了回答问题所需的所有信息。

**核心思想**：

- 将参考答案分解为多个独立声明

- 检查每个声明是否能从检索到的上下文中找到支持

- 关注"需要的信息是否都被检索到了"

**计算公式**：

```plaintext
Context Recall = 受上下文支持的参考答案声明数 / 参考答案总声明数
```

**示例**：

```plaintext
查询：法国的首都是什么？人口多少？
参考答案：巴黎是法国的首都，人口约220万。

检索上下文：巴黎是法国的首都，位于塞纳河畔。

分析参考答案声明：
- 声明1："巴黎是法国的首都" ✓ 受支持
- 声明2："人口约220万" ✗ 不受支持

Context Recall = 1/2 = 0.5
```

**实现机制**：

1. 从参考答案中提取所有声明

2. 使用 LLM 判断每个声明是否能从上下文中推导

**取值范围**：0-1，需要标准答案。

---

#### 7. 上下文实体召回率 (Context Entity Recall)

**定义**：衡量检索到的上下文是否覆盖了参考答案中的所有关键实体。

**核心思想**：

- 从参考答案中提取命名实体（人名、地名、组织等）

- 检查这些实体是否出现在检索到的上下文中

- 关注关键信息的完整性

**计算公式**：

```plaintext
Context Entity Recall = 上下文中出现的参考答案实体数 / 参考答案总实体数
```

**示例**：

```plaintext
参考答案：乔布斯和沃兹尼亚克在1976年创立了苹果公司。
提取实体：乔布斯、沃兹尼亚克、1976年、苹果公司（4个）

检索上下文：史蒂夫·乔布斯在1976年创立了苹果。
匹配的实体：乔布斯、1976年、苹果（3个）

Context Entity Recall = 3/4 = 0.75
```

**实现机制**：

1. 使用 NER 或 LLM 从参考答案中提取实体

2. 检查每个实体是否出现在上下文中（模糊匹配）

**取值范围**：0-1，需要标准答案。

## 四、RAGAS 指标体系总结

| 指标 | 评测对象 | 是否需要参考答案 | 核心关注点 |
| --- | --- | --- | --- |
| **Faithfulness** | 生成器 | ❌ 否 | 幻觉检测 |
| **Answer Relevancy** | 生成器 | ❌ 否 | 回答切题度 |
| **Answer Correctness** | 生成器 | ✅ 是 | 事实准确性+完整性 |
| **Answer Similarity** | 生成器 | ✅ 是 | 语义相似度 |
| **Context Precision** | 检索器 | ✅ 是 | 检索内容的有用性 |
| **Context Recall** | 检索器 | ✅ 是 | 检索内容的完整性 |
| **Context Entity Recall** | 检索器 | ✅ 是 | 关键实体的覆盖度 |
