## 通用Checklist

- [ ] 页面整体性能

  - [ ] **Action**: 关键请求是否添加预加载？关键资源是否添加预请求？[数据预取能力配置](https://docs.xiaohongshu.com/doc/709e7ccc4b3aaafc3d7ff8c1ccb3400f)

  - [ ] **Action:** 图片放大和浏览，是否使用了交易原生的黑灯页？[黑灯页bridge](https://docs.xiaohongshu.com/doc/049b1cada4d56aae100c87093f6882b5)

  - [ ] **Action: **应用是否需要接入强更forceUpdate强刷？

  - [ ] **Measure: **页面是否接入默认 or 自定义Fmp测量？ [APM 使用文档 - RN 接入首屏默认 FMP 及其分阶段指标](https://docs.xiaohongshu.com/doc/4f42cb3e3265cb2a2d69d18a6cb2c00e)

  - [ ] **Measure: **如果含滚动列表，页面是否接入滚动卡顿率检测？[指标接入技术文档](https://docs.xiaohongshu.com/doc/99660a21d8cec5643af8fc6aac039903)

- [ ] 涉及列表场景

  - [ ] 是否涉及列表加载？列表的平均和最大数据量级是多少 [长列表场景](https://docs.xiaohongshu.com/doc/b52f0fdee9193c1236ebae77fdf3dc71)

  - [ ] 技术方案设计时：如果列表数据量大，是否使用了 flatlist，@shopify/flashlist 等虚拟列表方案？

  - [ ] 开发时：是否设计了合理的 estimateditemsize  算法使得无限列表可以得到合理的预估高度？离屏渲染高度是否足够，使得触底率达标？[长列表触底预取标准](https://docs.xiaohongshu.com/doc/21aba4798c0972a5a888eeadc557041c)

  - [ ] 埋点上报：如果没使用虚拟列表方案，是否需要接入(Spectrum的Viewable.View或者Flatlist的onViewableItemChanged)？

  - [ ] 回归：是否让QA 回归了大数据量（100+数据）场景下的页面的可用性和性能？

- [ ] 涉及多图场景[图片接入方案](https://docs.xiaohongshu.com/doc/429e31f3635b3ae2ebdfc44da9de8680)

  - [ ] 技术方案设计时：服务端是否接入了[图片播控服务介绍](https://docs.xiaohongshu.com/doc/15c2df469d0ab65ea2d2f38405c28afc)？ 

  - [ ] 图片渲染是否使用标准组件（大图模式参数，安卓优化参数，fade=0）？

  - [ ] 回归：是否让QA 回归了大数据量（100+数据）场景下的页面的性能与可用性（图片全部加载）？

- [ ] 涉及半屏场景 [半屏容器组件](https://docs.xiaohongshu.com/doc/fead63eb83c9c5a8f59de28a090f7ed7)

  - [ ] 非特殊情况外，半屏统一使用客户端半屏，接入方式使用Infra组件

- [ ] 是否支持黑暗模式，接入请查看 [主题样式Token使用文档](https://docs.xiaohongshu.com/doc/3f015bb1454d99fd01ad6a8230f1f73d)

- [ ] 涉及实验和配置[AB实验接入](https://docs.xiaohongshu.com/doc/678c74c522c60e7f94352f52f91ef758)

  - [ ] 哪端创建实验并读取实验值？

  - [ ] 实验生效端是否为“**客户端-多端”**？

  - [ ] 开发中：实验下发的值是否是** String 类型的值**？如果不得不处理非 String 类型的值，是否做了合适的类型转换？

case：[【笔记评论分析安卓实验漏出】复盘文档](https://docs.xiaohongshu.com/doc/ef09855c29d846a2b4343e9ebb211ee9)未做数字化处理导致对照组也可以看到实验中模块

  - [ ] 自测与回归：是否同时针对实验组、对照组、非实验流量 三种场景都做了验证？ 

  - [ ] 代码上线前：是否每个flag的表现都符合预期，是否做好拉到配置和没拉到配置的场景处理。如果用户还没拉到配置，前后端客户端的表现是否正常？

  - [ ] 合码后：是否约定了代码固化的责任人和大致的时间节奏？

- [ ] 稳定性和发布方案

  - [ ] **发布：**是否和后台明确发布计划和模块上线顺序（包括前端、后台、apollo配置、实验放量等）？

  - [ ] **稳定性：**是否设计了除了代码版本回滚以外的了快速止损方案？如 回滚范围、switch 配置下发、服务端 apollo 开关方案；

  - [ ] **稳定性：**是否补齐了基础的埋点sdk 和 JS Error/ Http/ RN 应用崩溃等告警能力？（参考 APM 创中者中心creator-center 告警维度）

  - [ ] **稳定性：【**核心流程】兜底加自定义埋点上报，对关键链路（如订单支付等动作）添加流程埋点上报

- [ ] 涉及客户端的新增、改造

  - [ ] 前端是否可以同时兼容新老版本？

  - [ ] 是否涉及版控？由哪一端实现版控？ 

  - [ ] QA 侧，是否在最新客户端版本和客户端-1 版本都进行了验证？

- [ ] <font color="rgba(0, 0, 0, 0.85)">RN版本覆盖节奏 </font>

  - [ ] <font color="rgba(0, 0, 0, 0.85)">是否页面要进入内置包</font>

  - [ ] <font color="rgba(0, 0, 0, 0.85)">是否有拉包兜底页</font>

- [ ] 跨页面能力设计

  - [ ] **关注、点赞、评论**等交互行为是否有跨页面数据同步诉求？是否设计了基于 crossPlatformEvent 事件或者 storage 的数据同步机制？

  - [ ] 正向链路是否有强插诉求？是否需要后台配合实现？

- [ ] RN资产共建

  - [ ] 是否有可以借助本次需求沉淀的RN物料/资产？组件、hook、还是模块形式的资产？

  - [ ] 共建的资产形态是怎样的？是简单的SOP文档，还是可复用代码端，还是npm package?

  - [ ] 如果是业务资产，是否跟产品确认长期的迭代形态？
