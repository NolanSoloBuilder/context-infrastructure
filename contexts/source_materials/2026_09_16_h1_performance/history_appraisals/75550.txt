Agent能力&出码能力建设和落地

3月正式开始进入AI会场相关开发，完成会场 Agent workflow 的能力支持和流程串联，设计整体数据流程和对话流交互，针对多轮对话提供意图分析 Agent，过程的实现和落地，总结了agent以及ai出码的相关工作机制，对后面打下一个基础。

Agent能力建设：

1.
基于新架构重新实现并优化了会场AI内的可交互的agent工作流，抽象了可以服务多个场景的通用plan+可交互步骤执行工作流。可以复用到RN搭建等场景。
2.
能力上，搭建plan agent， 意图识别，工作流context持久化等能力。

D2C落地：

1.
从6月开始，本地所有需求走D2C，在整个过程，对于偏展示类场景，整体提效明显，受限于UI还原度问题，仍然需要人工二次调整。
2.
在7-8双月我们RNcoding落地完整10+个需求
﻿
D2C集合
，小红卡系列需求页面100%覆盖，页面或者组件d2c包括：C端订单，核销，签约等场景，样式准确率在90%左右。

AI Coding 能力建设：

1.
根据页面直出场景和BDD场景建立RN出码标准，包括：代码规范，目录规范，样式，路由等，目前vibe和muse都遵循这套出码标准，系分标准需要联动客服一起再看下，如果完成业务直出目前的描述不够。
2.
线下 IDE链路：从整个研发环节考虑，除figma to cursor 外，提供了联调MCP，RN+Web 的调试MCP。目前线下链路的能力已经串联，但UI出码准确率60%左右，debug 使用率不高，整体的落地和效果需要进一步提升。UI出码需要更换到新链路。

问题&思考：

1.
D2C 能力落地的效果还比较好，优化后，整体的样式可用性比预期要高，组件场景的样式误差依旧存在，目前通过badcase来看，RN nativewindui+tailwind-variants 可能要比组件知识召回要好，具体效果差距需要验证。包含完整交互的出码是D2C的下一步，而如何精准正确使用业务规范组件以及业务场景方案的召回使用也是后续需要重点去看的部分呢。
2.
从出码角度无论线上线下，Code Agent 是最基础的能力，架构分层上需要像claude code 看齐，因为我们的场景更聚焦，系统复杂度会小，叠加过程的业务定制（context，资产召回，最终前端出码的可用性要比通用code Agent更强，一些安全等边界能力设计可以删减。

思考与复盘

在上半年中，本地相关业务依旧存在动态性比较强的特点，在前端视角下，采用不变应万变的策略，同时积极面对变化的态度去支撑和赋能整体业务的迭代，整体上，对问题的解决是积极和快速的，但是问题的数量是较多的，这个在小红卡结束后，需要进一步的复盘，在技术方案/预案和过程保障上都有进一步的空间。技术上，主要的认知迭代在AI Coding场景，明显感觉到每个双月都是一个台阶的上升，从线下到线上，从能力到场景，过程的能力积累最终反馈到实际的业务落地上，例如在小红卡业务上，我们利用AI能力验证并实现了D2C出码可以大幅提升开发速度（30-40%），减少了项目的开发周期。还有一些思考和反思，上半年每个双月过程的事情判断和分析没有太大问题，但项目过程的小节奏的跟踪需要进一步加强。
