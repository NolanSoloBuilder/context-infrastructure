# Build in Public

把零散开发记录压缩成一个有事实、有判断、有读者价值的内容单元，再分别生成平台原生版本。公开的是经过筛选的真实过程，不是完整工作日志。

## 工作流

### 1. 锁定内容窗口

确认项目、受众和时间范围。用户说“最近”“这周”时，将其转换为绝对日期。信息足够就直接执行；缺少关键范围且无法从当前仓库判断时，只问一个最影响结果的问题。

默认一次输出一个主题。多个进展先排序，不把互不相关的更新拼成一篇。

### 2. 收集原始材料

按请求范围读取可用真源：

- 用户提供的想法、聊天记录、语音转写或工作日志
- Git commit、diff、PR、issue 和测试结果
- 产品文档、设计稿、截图、部署结果与真实指标
- 失败记录、被否定的方案和决策原因

用户只要求基于所给材料时，不扩大到整个工作区。用户要求“整理最近开发进度”时，先查看目录路由与仓库状态，再读取目标时间窗内的相关证据。

### 3. 建立事实账本

写作前在内部区分四类信息：

| 类型 | 含义 | 写作规则 |
|---|---|---|
| 已验证事实 | commit、测试、线上结果、用户明确陈述 | 可以确定表达 |
| 用户想法 | 判断、动机、感受、假设 | 以第一人称观点表达 |
| 推断 | 从材料推出来但尚未确认 | 标注为推测，或从正文移除 |
| 计划 | 下一步准备做的事 | 使用未来时，不写成既成结果 |

禁止虚构用户数、收入、耗时、性能、反馈、发布日期或个人感受。证据不足时保留空缺，必要时在交付中列出待补信息。

### 4. 选择一个叙事核心

优先选择同时满足以下条件的进展：

1. 有具体变化：做成、改掉、发现失败原因或改变决策。
2. 有可复用认识：读者能带走一个判断、方法或避坑点。
3. 有公开证据：界面、数字、代码变化、测试或明确过程。

把主题压缩成一句话：

> 我原本认为 `[旧判断]`，在完成 `[具体动作]` 后发现 `[新判断]`，证据是 `[事实]`。

不强行制造反转。没有旧判断时，使用“目标 → 约束 → 选择 → 结果”。

### 5. 生成共享内容 Brief

先形成两个平台共用的内容真源：

- 一句话主题
- 目标读者
- 公开安全的事实与证据
- 决策或冲突
- 得到的认识
- 当前状态与下一步
- 可选互动问题

具体格式和平台合同见 [platform-contracts.md](references/platform-contracts.md)。需要批量整理素材时，使用其中的 Progress Packet。

### 6. 分别改写，不做机械搬运

默认输出一篇小红书笔记和一条 X 单帖。

小红书侧强调完整情境、过程细节和可读性；X 侧强调一个观察、一个证据和一个判断。内容天然包含连续的因果链、步骤或多项证据时，才把 X 改成 thread。

小红书默认给出 3 个标题候选并选定 1 个。标题保持真实，不用无法兑现的结果承诺。用户明确追求标题优化时，可以读取并使用 `../dbs-xhs-title/SKILL.md`，但事实边界与本 Skill 冲突时，以本 Skill 为准。

### 7. 做发布前门禁

逐项检查：

- 每个结果、数字和引语都有来源。
- 帖子表达了一个清楚的变化或判断。
- 两个平台保留同一事实真源，但语言和结构各自原生。
- 没有 secrets、token、内部域名、未公开客户信息、同事隐私或敏感截图。
- 没有把计划写成结果，也没有把推断写成用户反馈。
- CTA 与当前阶段一致，不假装已经开放注册、上线或盈利。

小红书发布前，可读取 `../xiaohongshu-content-checker/SKILL.md` 做合规检查。平台规则会变化，检查结果属于风险提示，不代表平台最终判定。

## 默认交付格式

```markdown
## 内容 Brief
- 主题：
- 目标读者：
- 事实依据：
- 核心判断：
- 未确认信息：

## 小红书
### 标题候选
1.
2.
3.

### 推荐标题

### 正文

### 标签

### 封面短句（可选）

## X
### 推荐版本

### 备选 Hook（可选）

## 发布前检查
- 事实：
- 隐私：
- 平台：
```

用户只要成稿时，隐藏内部 Brief，只交付帖子与必要的风险提示。用户要复盘或可追溯过程时，保留 Brief 和事实依据。

## 发布边界

默认停在草稿。用户明确要求发到 X、创建草稿或排期时，先读取 `../../../rules/skills/typefully_post.md`，校验 weighted count，再按用户授权执行。任何公开发布、排期或向外部平台写入的动作都需要本轮明确授权。
