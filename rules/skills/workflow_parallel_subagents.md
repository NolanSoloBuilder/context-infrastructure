# 并行 Subagent 工作流

适用于准备委派独立子任务时；简单任务直接串行，无需为形式增加 Agent。

## 判断与分工

- 至少有两个相对独立、工作量足够的部分，且节省的等待时间能抵消上下文传递与整合成本时才委派；工具调用次数仅作估计，不设硬门槛。
- 通常从 2–3 个 Agent 开始，并发上限以当前运行环境为准。重型构建、全量测试和批量浏览器验证仍遵守本机调度规则。
- 每个子任务给清目标、输入来源、文件范围、允许动作、交付格式和验证责任；避免多个 Agent 修改同一文件。
- 调研可安排必要的独立复核，代码任务减少重叠；不按固定百分比制造重复工作。主 Agent 负责整合与检查关键证据。

## 当前运行环境

- 只使用当前暴露的工具与参数，不把其他 Agent 产品的 API、模型路由或等待语义套过来。
- Codex：按当前工具 schema 使用 `collaboration.spawn_agent`、`send_message`、`followup_task` 和 `wait_agent`。创建子 Agent 不等于创建用户侧新聊天。
- 派出后继续主任务中可独立完成的部分；需要结果时有界等待或接收系统通知，避免频繁查询。等待时保持必要进度沟通，不因派出子任务而提前结束尚未完成的主任务。
- OpenCode：仅在实际使用该运行时且对应工具可用时，使用其 `mcp_task`、category 或后台结果 API，并以该工具当前说明为准；不假设通知与阻塞行为。
- 默认使用当前环境的模型选择。用户点名 Gemini/Sonnet 等模型时，核对已有路由；配置在 `~/.config/opencode/oh-my-opencode.json`，只对相应环境适用。不为普通创意任务固定增加另一个模型。

## 整合与收尾

- 验证结果是否覆盖约定范围，标明未知和未完成事项；继承的父会话历史不计为子 Agent 新执行的证据。
- 中间结果通常由主 Agent 整合，不各自生成重复报告。可逆工作自主推进，外部发送及不可逆操作遵守用户授权。
