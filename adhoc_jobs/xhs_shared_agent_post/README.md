## 推荐标题

每个人都用上 AI 了，团队为什么还没变快？

## 正文

前几天看了张咋啦关于 AI 原生工作方式的分享。她说了一句话：

个人效率的提升，不等于团队效率的提升。

听到这里的时候，我一下就对上了。

倒不是因为这是一个多新的概念，而是她描述的方向，和我前段时间一直在琢磨、也实际尝试过的事情很像。

我试过把前后端仓库、产品文档、会议记录和执行结果放进同一个 Workspace，让 Agent 能接着团队之前的上下文继续工作；也试过把会议里的讨论变成工作项，再往执行、测试和结果写回推进。

做这些尝试的时候，我越来越明显地感觉到一个问题：现在的 AI，大部分还是一个人的 AI。

同一个需求，产品在飞书里讨论，设计在 Figma 里修改，前端拿去问 Codex，后端又在另一个会话里分析接口。看起来每个人都用上了 AI，也确实都比以前快了一点。

但这些 AI 彼此不知道对方做过什么。

需求为什么这样定，会议里争论过什么，某个技术方案为什么被放弃，仍然散落在聊天、文档和每个人的个人会话里。一个人刚刚补全的背景，换一个人、换一个 Agent，又要从头讲一遍。

于是出现了一个有点矛盾的结果：每个人都变快了，团队共同的上下文还是断开的。

我现在越来越想做的，是让 Agent 真正进入人与人的协作。

比如，一个产品研发团队可以共用产品 Agent、设计 Agent、前端 Agent 和后端 Agent。它们不是某位同事的数字分身，也不属于某一个人，而是整个团队共同维护和使用的能力。

大家在群里讨论需求时，可以直接 `@产品 Agent`，问它以前为什么放弃过类似方案；也可以 `@前端 Agent`，让它看看会影响哪些页面；再问问 `@后端 Agent`，现在的接口到底能不能支持。

它们看到的是同一个 Workspace：产品文档、设计稿、前后端仓库、会议记录、群聊和历史决策。这样，团队不需要每次都从零开始补背景。

会议结束以后，逐字稿可以先整理出接下来要做的事情。人来确认目标和范围，Agent 再去修改、测试，把代码、截图和验证结果交回来。做完的结果继续留在 Workspace 里，下一次讨论可以直接接着往下走。

我不希望 Agent 替人做最终决定，也不希望它假装成团队里的某一位同事。

我更希望它像团队共同拥有的一组能力：知道事情之前是怎么讨论的，知道现在进行到了哪里，也能把这一次做完的结果留给后来的人。

这件事我还在继续尝试，产品最后应该是什么样子，也没有完全想清楚。但有一点我越来越确定：AI 的价值不应该只停在让一个人做得更快。

过去我们一直在研究一个人怎么和 AI 协作。接下来，我更想知道：

当 AI 真正进入人与人的协作，团队会变成什么样？
